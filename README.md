# vertex-learning-platform

Vertex is an AI-powered learning platform with intelligent content search. Authors
create courses in Sanity; a Next.js site serves them to learners. A learner types a
plain-language query and gets back ranked, clickable cards — each linking to the
exact second in a lesson's video where that topic is taught, played on the site.

## Stack

- **Next.js** (App Router) + TypeScript + Tailwind v4
- **Sanity** for the content model, via `next-sanity`
- **Clerk** for authentication
- **PostHog** for product analytics
- **Sanity Context MCP** + Vercel AI SDK for search

## Two workspaces

The repo holds two standalone workspaces that deploy independently (AGENTS.md §5):
the Next.js web app at the repo root, and the Sanity Studio in `studio/`. The
Studio is deliberately *not* embedded in Next.js — that is what keeps Studio
auto-updates, fast Vite builds, and TypeGen watch mode.

## Getting started

```bash
# web (repo root)
cp .env.example .env.local   # fill in Clerk + Sanity, incl. SANITY_API_READ_TOKEN
npm install
npm run dev                  # http://localhost:3000

# studio (separate terminal)
cd studio
cp .env.example .env.local   # same project id and dataset
npm install
npm run dev                  # http://localhost:3333
```

## Checks

```bash
npx tsc --noEmit   # types
npm run lint       # lint
npm run build      # production build

cd studio
npm run typegen    # regenerates ../sanity.types.ts from the schema + queries
npm run deploy     # required before the Context MCP will serve the dataset
```

## Video ingestion

Search resolves a query to an exact second using `video` documents: one per video
URL, holding the source's chapter markers and its transcript in short timestamped
chunks (AGENTS.md §8, §9). They are built by offline tooling and never touched in
the request path.

```bash
cd studio
npm run ingest:fetch     # network stage → scripts/ingest/sources/transcripts.ndjson
npm run ingest:prepare   # offline transform → .out/videos.ndjson
npm run ingest:import    # prepare + dataset import
```

`sources/transcripts.ndjson` is a committed input, like `seed.ndjson`: it keeps the
transform deterministic and survives a provider changing its endpoints. `fetch` is
incremental — it skips videos already ingested, so a throttled run resumes by
re-running it (`--force` refetches, `--only <videoId>` does one).

## Design system

The visual language lives in `app/globals.css` (tokens) and `app/components/ui/`
(primitives: buttons, inputs, badges, status indicators, progress, cards,
navigation). Reference designs are in `design/`.

`/style-guide` renders every token and primitive side by side so it can be diffed
against `design/vertex-designsystem.png`.

## Repo layout

| Path                 | What's in it                                     |
| -------------------- | ------------------------------------------------ |
| `app/`               | Next.js routes and UI components                 |
| `sanity/`            | Server-only read client, fetch helper, GROQ queries, derived-value helpers |
| `sanity.types.ts`    | Generated by Sanity TypeGen — do not edit by hand |
| `studio/`            | Sanity Studio workspace: the content model, seed, context, and video ingestion |
| `design/`            | Design reference images (source of truth for UI) |
| `prompts/`           | Implementation prompts, one per work item        |
| `.agents/skills/`    | Vendored agent skills (pinned by `skills-lock.json`) |
| `AGENTS.md`          | How this project is built and what it must do    |
